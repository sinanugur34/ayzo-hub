# AYZO Wave 30 — Handoff

Wave 30 begins only after Wave 22 production release is completed.

## Baseline

The existing 22 networks are regression baselines and must not be
weakened to add more network count.

Wave 30 adds exactly eight networks: 23 through 30.

## Expansion standard

Every new network must satisfy the same production contract:

1. canonical network registry
2. native address validation
3. native provider architecture
4. bounded evidence normalization
5. Free / Pro / Advanced plan depth
6. public web intelligence route
7. mobile intelligence route
8. public API v1
9. web Evidence Workspace
10. mobile Evidence Workspace
11. Ask AYZO
12. Historical Evidence
13. Advanced Batch Analysis
14. truthful product capabilities
15. live provider smoke
16. full regression suite
17. TypeScript
18. lint
19. mobile production build
20. web production build
21. canonical/product/mobile parity

## Candidate rule

A network will not be added merely to increase the displayed number.

Selection should prioritize:

- actual user/research demand
- ecosystem activity
- dependable production data access
- evidence depth AYZO can truthfully provide
- provider reliability and rate limits
- clear differentiation from existing networks
- sustainable ongoing maintenance

Aptos and NEAR remain candidate networks, not yet locked members of
Wave 30.

## Architecture rule

Shared execution families may reuse infrastructure only where the
underlying evidence semantics genuinely match.

Native networks retain native evidence models.

No fake feature parity is allowed.
